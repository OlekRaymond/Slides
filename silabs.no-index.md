### Compiler flags
 - "-g" should be turned off for our release builds,
   + I understand why it's on by default but please add a way (in cmake!) to turn it off
      * The symbol table is a significant size and I do not need (nor want) it in production.
      * Assuming C++ is going to become more common in the stack, the problem will only become larger over time
      * It's also subject to change, e.g. a rename, and we use the exe hashes to determine if code is the same
      * It often makes code slower because optimisations such as vectorisation do not lend themselves to debugging so are often removed
   + The optimiser does a lot less with debug symbols turned on, but more importantly it leaks IP and data about our source code
   + CMake knows what the compiler flags are and supports various build configurations out of the box; Debug, Release, RelWithDebInfo, MinSizeRel. If these were supported instead of hard coding flags our products would be much more secure.
   + For CRA compliance we will have to turn debug symbols off.
 - More information can be found in [CMake's documentation](https://cmake.org/cmake/help/latest/variable/CMAKE_BUILD_TYPE.html), some codebases will add more

[//]: # (Vertical slide)

### Unity builds
 - C and C style C++ projects often use many translation units, with little to no code written in header files. Having lots of small translation units increases the build times and link time significantly.
   + To maintain the ease and encapsulation that multiple files offer, C developers started using unity builds (also known as jumbo builds or amalgamations).
   + A unity build merges many translation units into a single larger one. As more inlining can be done at the compile step the linker has to find less symbols to link each function to.
   + A unity build used to in
   + (C++ developers used header files, templates and the `inline` keyword to allow code in headers, reducing the number of translation units. Then in C++20 modules where introduced which massively increase compilation and link speeds)

[//]: # (Vertical slide)

 - CMake has native support for unity builds which can be easily enabled/disabled. Because certain languages are more difficult to do this in than C++, CMake offers a build mode: group, which the library maintainer can decide which files are allowed to be build together and which ones cannot.
  + I have done a lot of this for myself which you are welcome to use.

[//]: # (Vertical slide)

```CMake
  include(unity_build_groups.cmake OPTIONAL RESULT_VARIABLE managed_unity_groups)
  if (managed_unity_groups)
    set_target_properties(${PROJECT_NAME}_slc PROPERTIES UNITY_BUILD_MODE GROUP)
  else()
    set_target_properties(${PROJECT_NAME}_slc PROPERTIES UNITY_BUILD OFF)
  endif()
```

[//]: # (Vertical slide)

```C++
template<typename T,size_t A, size_t B>
consteval auto Combine(std::array<T, A>&& a, std::array<T, B> b) {
  std::array<T, A+B> result{};
  std::copy(a.begin(), a.end(), result.begin());
  std::copy(b.begin(), b.end(), std::advance(result.begin(), A));
  return result;
}
```
